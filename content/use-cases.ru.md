# Для каких проектов

nuckty подходит для документации, руководств и контентных сайтов: автор пишет страницы в Markdown, разработчик управляет блоками интерфейса и сборкой.

## Документация

Руководства, справочники и архитектурные решения: ссылки на исходные файлы превращаются в адреса страниц по карте сайта. Заголовки получают иерархические якоря. Этот сайт собирает документацию nuckty из отдельного репозитория.

[Начните с руководства](/how/start), затем изучите [карту сайта](/how/sitemap) и [Markdown](/how/markdown).

## Контентные сайты

Статьи, инструкции и сообщества: текст хранится отдельно от блоков интерфейса. Галерея, сетка и видео добавляются расширениями; свои конструкции можно зарегистрировать через `env.markdown`.

[Готовые расширения](/ext) и [создание своих](/how/ext).

## Несколько языков и доменов

Таргет — один собираемый сайт. Несколько таргетов используют общие блоки, но отдельные карты сайта и выходные каталоги. Для родственных языковых версий движок передаёт данные `hreflang` обработчику документа. Переводы подготавливает автор.

[Как настроить таргеты](/how/targets).

## Виртуальный хостинг

Сборка готовит HTML, ассеты, Brotli и Gzip, манифест и конфигурацию nginx и Apache. Расширение `deploy-ftp` публикует артефакт по FTP или FTPS. На сервере нужны совместимые модули и настройки.

[Что лежит в артефакте](/out) и [как настроить хостинг](/out/hosting).

## Когда понадобится другой инструмент

Если основная задача — динамические данные, серверная авторизация или приложение с постоянным состоянием, nuckty соберёт только статическую часть. CMS, серверный API и визуальный редактор не входят в ядро. Клиентский JavaScript можно добавить в блоки; живой пример есть в демо.
