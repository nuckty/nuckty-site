# Статический хостинг

CI собирает и проверяет оба языка, сохраняет готовые артефакты и затем автоматически публикует main по SSH. Pull request собирается и проверяется без доступа к ключу деплоя. Публикация npm-пакетов не требуется: ядро и расширения берутся по точным SHA исходников.

На VM передаются только каталоги ru/ и en/. Отдельные пользователи site/demo не имеют sudo; каждый ключ ограничен командой receive.py своего проекта. Приёмник проверяет размеры и хэши всех файлов манифеста, отвергает небезопасные архивы, переключает оба языка одной ссылкой current, проверяет главные страницы и возвращает предыдущий релиз при сбое. Сохраняются пять релизов; старый запуск CI не может заменить более новый.

Администратор устанавливает receive.py как /usr/local/libexec/nuckty-deploy.py и создаёт /srv/nuckty/{site,demo}/releases с владельцами deploy-пользователями. render-nginx.py адаптирует maps и locations из конфигурации движка для отдельных virtual hosts на втором интерфейсе, сохраняя слушающие порты прокси. TLS использует certbot webroot и reload при продлении сертификата. Сам деплой не требует reload nginx или перезагрузки VM.

GitHub Secrets: NUCKTY_DEPLOY_KEY. Переменные репозитория: NUCKTY_DEPLOY_HOST, NUCKTY_DEPLOY_USER, NUCKTY_KNOWN_HOSTS и закреплённые ссылки на исходники. Приватные ключи не должны попадать в Git. Контакт: vitaly@harisov.name.

Перед изменением приёмника выполните python3 -m unittest discover -s deploy -p 'test_*.py'. Публичные адреса: nuckty.ru/nuckty.com и demo.nuckty.ru/demo.nuckty.com.

На втором IP используется SNI: четыре домена nuckty идут на внутренний HTTPS listener 127.0.0.1:8445, остальные имена — в существующий Reality backend. Прежний redirect 443→9000 в nftables удалён; остальные правила firewall сохранены.
