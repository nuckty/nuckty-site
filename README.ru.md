# nuckty-site

Сайт описания nuckty и каноническая документация. Русский и английский таргеты используют общие блоки и соответствующие адреса. В обоих подключены указанный новый логотип в SVG и отдельный квадратный favicon на основе его знака. Стартовый проект устанавливает точные версии ядра, root и serve из публичного npm; расширения добавляются из npm.

Вкладки примера на главной показывают фактические BEMJSON, файл шаблона и HTML текущей сборки. Документация идёт от начала работы к модели данных; разделы на телефоне раскрываются кнопкой «Разделы».

Сборка сайта использует Python 3 для упаковки стартового проекта. Для установки и сборки скачанного проекта Python не нужен. Проверка архива: `npm run test:starter`; флаг `-- --preview` проверяет просмотр, изменение, пересборку и остановку (или `NUCKTY_NPM_CACHE=/путь/к/кешу npm run test:starter -- --offline`).

## Сборка и проверки

Нужны Node.js 24+, npm и каталог `../nuckty-docs`. Пакеты Nuckty устанавливаются из публичного npm; соседние исходники ядра и расширений не нужны.

```bash
npm ci
npm run build
npm run lint
npm test
npm run validate
```

`build` локально подготавливает документацию и вызывает `nuckty build`. Результат — в `site/ru/` и `site/en/`. Документация, карты сайта и данные поиска генерируются и исключены из Git; правьте канонические исходники `../nuckty-docs` или описание продукта в `content/`. `test` проверяет ссылки, якоря, ассеты, ID, размеры и хэши манифеста, распаковку Brotli/Gzip, логотип и hreflang. Для Nu Html Checker нужна Java.

## Локальный просмотр

Нужен nginx. Запустите в отдельных терминалах:

```bash
npm run serve       # http://localhost:8091
npm run serve:en    # http://localhost:8093
```

Для демо на порту 8092 запустите `npm run serve` в `../nuckty-demo`. Остановка — `npm run stop` и `npm run stop:en`. У английского просмотра свои PID и конфигурация nginx.

Локальные ссылки между проектами и языками заданы в `config/config-nuckty.ts`. Перед публикацией замените их выбранными публичными адресами. Канонические метаданные используют nuckty.ru/nuckty.com; сами скрипты ничего не публикуют.

## Исходники

`blocks/root` отвечает за документ, навигацию и содержание страницы. `home` и `card` собирают главную и настоящий пример nu. `search` даёт локальный поиск по тексту документации; `shell` — тему, меню и копирование кода. В `blocks/brand` лежат точный логотип, вариант для тёмной темы, favicon и лицензия. Общие правила проекта — в `AGENTS.md`.

Поиск использует Orama JS 3.1.18 со стеммингом русского и английского текста. Индекс включает полный Markdown, блоки кода, исходник главной и страницы применения — 52 адреса на каждом языке. Движок выпускается отдельным ES-модулем с хэшем, данные текущего языка — JSON в `search-index.txt`. Оба файла загружаются в свободное время браузера после отрисовки страницы либо сразу при открытии поиска. Прогресс считается по размеру несжатых данных UTF-8 и работает при отдаче gzip/Brotli; подготовка индекса имеет свой индикатор. Запросы обрабатываются локально, должны найтись все слова, заголовки имеют больший вес, чем текст. Если точных совпадений токенов нет, допускается небольшая опечатка; короткие термины вроде `nu` остаются точными. Совпадения подсвечиваются текстовыми узлами. На телефоне гамбургер открывает поиск и полную карту сайта, на десктопе лупа превращает всю шапку в поле. Escape возвращает фокус, переход между мобильным и десктопным режимами закрывает панель. `npm test` проверяет оба языка, собранный модуль и метаданные прогресса.

## CI исходников

Workflow `CI` устанавливает пакеты по registry lock-файлу и получает только каноническую документацию по последнему коммиту с успешным CI. Оба языка и самостоятельные npm-стартеры проверяются перед публикацией артефактов main. Публичные адреса: nuckty.ru/nuckty.com и demo.nuckty.ru/demo.nuckty.com; `npm run build:preview` включает локальные переходы.

## Обновление опубликованных пакетов

`.github/workflows/update-packages.yml` получает версии фиксированного набора официальных пакетов из публичного канала npm `beta` или `latest`. Выбранные точные версии хранятся в `config/config-packages.json`. При несовместимых peer dependencies ядра обновление останавливается. После чистой установки и проверок потребителя workflow создаёт коммит с версиями и lock-файлом, затем явно запускает CI с деплоем; неизменившийся набор не создаёт коммит. Workflow публикации пакета запускает обновление после проверки реестра.

Карта версий деплоя также подставляет версии в команды установки официальных npm-пакетов из канонической документации; обычный текст и сторонние примеры сохраняются. Эта же карта используется для starter-архивов.
